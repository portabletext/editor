The editor API provides access to the editor instance and selectors for deriving state.

Use the following hooks to access the editor from within your components.

## `useEditor`

Access the editor instance. Commonly used when building toolbars or passing snapshot to selectors.

```tsx
import {useEditor} from '@portabletext/editor'

const editor = useEditor()
```

## `useEditorSelector`

Access selectors in areas where the snapshot is available by combining with `useEditor`.

```tsx
import {useEditor, useEditorSelector} from '@portabletext/editor'
import * as selectors from '@portabletext/editor/selectors'

const editor = useEditor()
const isActive = useEditorSelector(editor, selectors.isActiveDecorator('em'))
```

An optional third argument, `compare`, decides whether the selected value has changed. It accepts the previous and next values and returns a boolean. The default is reference equality (`===`).

## `editor.on`

Register a listener for events the editor emits: `editor.on(type, listener, options?)`, where `options` is `{batch?: boolean}` (default `false`), returning `{unsubscribe: () => void}`. Pass an event type, or `'*'` for every event. A specific event type narrows the event the listener receives to that type.

By default the listener runs synchronously for every matching event and receives a single event.

With `{batch: true}` the listener receives an array of events instead, narrowed the same way. The first matching event schedules a microtask, and the listener is called once when it runs, with every matching event delivered until then, in delivery order. Events emitted after that start a new batch. No events are dropped. Two synchronous `editor.send` calls coalesce into one batch. A listener that unsubscribes before the microtask runs gets no call for that batch.

```tsx
import {useEditor} from '@portabletext/editor'
import {useEffect} from 'react'

function OperationLogger() {
  const editor = useEditor()

  useEffect(() => {
    const subscription = editor.on(
      'operation',
      (events) => {
        console.log(events.map((event) => event.operation.type))
      },
      {batch: true},
    )

    return () => {
      subscription.unsubscribe()
    }
  }, [editor])

  return null
}
```

## `editor.subscribe`

Subscribe to editor state changes: `editor.subscribe({next?, error?, complete?})`, returning `{unsubscribe: () => void}`. `next` is called with the current `EditorSnapshot`.

Notifications are coalesced. A synchronous burst of state transitions results in a single `next` call on the next microtask, with the snapshot read at that point. Intermediate states are skipped. To observe every operation, use `editor.on('operation', ...)`. The editor never calls `error` or `complete`. Calling `unsubscribe` also cancels a `next` call that is already scheduled.

```tsx
import {useEditor} from '@portabletext/editor'
import {useEffect} from 'react'

function SelectionLogger() {
  const editor = useEditor()

  useEffect(() => {
    const subscription = editor.subscribe({
      next: (snapshot) => {
        console.log(snapshot.context.selection)
      },
    })

    return () => {
      subscription.unsubscribe()
    }
  }, [editor])

  return null
}
```

## `keyGenerator`

Returns a random 12 character hexadecimal key generated with `crypto.getRandomValues`. The editor uses it when `initialConfig.keyGenerator` is not set.

```ts
import {keyGenerator} from '@portabletext/editor'

const key = keyGenerator()
```

## Types

### `BlockOffset`

A character offset into a block.

```ts nocheck
type BlockOffset = {
  path: BlockPath
  offset: number
}
```

### `BlockPath`, `ChildPath` and `AnnotationPath`

Aliases of `Path` that name what the path points at: a block in the value, a child of a text block, and an annotation `markDef` on a block.

```ts nocheck
type BlockPath = Path
type ChildPath = Path
type AnnotationPath = Path
```

### `Operation`

The document-changing operations delivered by `editor.on('operation', ...)` (beta). Selection changes are not included.

```ts nocheck
type Operation =
  | {
      type: 'insert'
      path: Path
      node: PortableTextTextBlock | PortableTextObject | PortableTextSpan
      position: 'before' | 'after'
    }
  | {type: 'insert.text'; path: Path; offset: number; text: string}
  | {type: 'remove.text'; path: Path; offset: number; text: string}
  | {type: 'set'; path: Path; value: unknown}
  | {type: 'unset'; path: Path}
```

For `set`, the path is `[...nodePath, propertyName]`. For `unset`, the path either ends in a property name, which removes that property, or in a keyed segment, which removes that node from its parent. `insert`, `set` and `unset` can also carry an optional `inverse`, whose presence is not a stable contract. Operation objects are passed by reference, so treat them as read-only.

### `AddedAnnotationPaths`

```ts nocheck
type AddedAnnotationPaths = {
  markDefPaths: Array<Path>
}
```

`markDefPaths` holds a path per `markDef` created for the annotation.
